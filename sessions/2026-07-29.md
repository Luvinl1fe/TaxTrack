## What was completed today

### Milestone 3 — SQLite schema + repository layer (PR #2)

- `src/db/schema.ts` — append-only `MIGRATIONS`, applied count tracked in
  SQLite's `user_version`. Tables: `receipts`, `wfh_logs`, `vehicle_trips`,
  `categories`.
- `src/db/mappers.ts` — pure row ↔ domain mapping that **validates rather than
  casts**, so a corrupt value throws instead of contributing `NaN` to a total.
- `src/db/database.ts` — open, migrate, seed. Memoises the *promise* so
  concurrent startup callers await one open.
- `src/db/receiptRepository.ts` — three SQLite repositories behind the
  interfaces in `src/domain/repositories.ts`.
- `src/domain/categories.ts` — the 14 approved categories, D1–D10 mapping
  verified. D6/D7/D8 present but `phase: 3` and filtered out, so enabling them
  later is a flag flip, not a migration.
- `src/domain/substantiation.ts` — the s 900-35 test, modelled as a **cliff**
  (over $300, *all* work expenses need evidence, not just the excess).

### Milestone 4 — Add/edit receipt + camera capture (PR #3)

- `src/app/receipt/[id].tsx` — one route serving create (`/receipt/new`) and
  edit. Merchant, amount, date, category, work-use %, photo, notes.
- `src/lib/money.ts` — cents ↔ dollars. Parsing works on the **digits of the
  string**, never `Number(x) * 100`, because `49.95 * 100` is
  `4994.999999999999` in IEEE 754.
- `src/domain/receiptForm.ts` — pure validation, deliberately outside the
  screen so it can be tested without a renderer. Reports every invalid field at
  once rather than one per submit.
- `src/lib/photos.ts` — copies picked images out of the **cache** directory into
  app documents before the URI is stored. The OS purges the cache, which would
  silently lose the evidence weeks later.
- `src/components/` — `CategoryPicker`, `FormField`, `PhotoViewer`.

### UI work driven by feedback

- **Long-press delete → visible red bin icon** with a confirmation naming the
  receipt. Standing principle, recorded in `KNOWN_GAPS.md`'s sibling guidance:
  every control must be discoverable, never a hidden gesture. The user is a
  PAYG taxpayer doing this once a year, not a power user.
- **Amounts and bin icons aligned into fixed columns** over tabular figures.
- **Dates display as `DD/MM/YY`** via `formatDateAu`. Storage stays
  `YYYY-MM-DD` — ISO sorts correctly as plain strings, which
  `ORDER BY purchase_date` relies on.
- **Date moved onto the merchant line**, category on its own line.
- **Full-screen pinch-zoom photo viewer** up to 8×, because a thumbnail can't
  be read by an accountant. Required adding `GestureHandlerRootView` to
  `src/app/_layout.tsx`.

## Context worth carrying forward

- **Working agreement:** branch per milestone → PR → squash-merge to `main`
  after review. Nothing is committed or pushed without being asked.
- **Expo SDK is pinned to 54**, not the latest. Expo Go on the user's iPhone
  caps at 54. Per `AGENTS.md`, read
  https://docs.expo.dev/versions/v54.0.0/ before writing any native-module code
  — the APIs have moved (e.g. `expo-file-system` is now `File` / `Directory` /
  `Paths` classes, with the old functions at `expo-file-system/legacy`).
- **`KNOWN_GAPS.md`** is the running record of what isn't covered. Add to it
  each milestone; gaps leave only by being closed, never deleted.
- **Two open blockers, neither ours:** the 2026–27 WFH fixed rate is still
  unpublished by the ATO (a 🔴 release gate for milestone 6), and monetisation
  is undecided (doesn't block Phase 1).
- **The device is the only real test.** The blank photo viewer bug typechecked,
  linted, bundled and passed 240 tests. Screens have no automated coverage by
  design — check new UI on the phone before calling it done.
